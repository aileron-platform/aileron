# 生命週期與存取

## 目的與入口

從工作區清單、建立精靈或生命週期控制進入，用於建立、啟動、停止、重新啟動、重設與永久刪除。

## 統一進入流程

工作區入口固定依序投影三個階段：身份（Identity）、工作區（Workspace）與執行環境（Execution）。身份與工作區權限尚未完成前，不會建立受保護的 Workspace Provider、查詢或執行平面連線；權限撤回時也會 fail closed。

三個階段共用同一個 Entry Gate 與固定版面。短暫等待不顯示進度面板；需要顯示時，面板至少維持固定時間，且導覽列位置不變。進入工作區後，功能本身的 lazy loading 改在 Workspace shell 內顯示內容區骨架，不再替換整個入口畫面。

## 角色與允許操作

生命週期操作要求 `workspace.lifecycle.execute`（manager）；永久刪除要求 `workspace.delete`（owner）。

## 核心概念

requested action、operation state、observed availability 與 generation 是不同狀態；按鈕只依 API 當次 `allowedActions`。

### 執行平面漂移

當控制平面宣稱目前 generation 可用，但對應 Pod／Container 不存在、部分缺失或 identity 不符時，Workspace 進入執行平面漂移。這不代表 Workspace 已刪除；控制面資料、持久資料與權限仍會保留，平台不會自動重建，也不會因偵測到漂移而自動刪除資料。

漂移期間 Entry Gate 保持 fail closed，不掛載 Runtime、Thread、Terminal、Browser、Canvas 或其他執行平面 Provider、query 與 WebSocket。具有 `workspace.delete` 權限的 Owner 只會看到永久刪除入口；沒有刪除權限的使用者會看到聯絡 Workspace 擁有者或平台管理員的提示，不提供 start、retry 或 rebuild。

## 主要流程

送出操作後追蹤 durable state；只有 observed state 收斂才完成。永久刪除由 Owner 以完整 Workspace 名稱提出單一 DELETE intent，平台會自動收斂 Automation 取消、執行平面清理、Workspace 控制面資料、持久資料與權限刪除。已不存在的 Pod／Container 視為該項清理已滿足，不會阻擋其餘刪除範圍收斂。

Frontend 以 `GET /api/v1/workspaces/{workspaceId}/availability` 讀取可用性，並只透過 `POST /api/v1/workspaces/{workspaceId}/availability/actions/{action}` 執行回應允許的 action。

## 永久刪除投影

Settings 與 Availability Gate 都使用完整 Workspace 名稱確認；平台在接受請求時重新比對目前名稱，名稱載入或比對失敗時不建立刪除工作。進行中的 intent 只有一個流程，重複請求沿用既有流程；失敗後才可重新確認名稱並以同一 DELETE endpoint 重試。刪除接受後鎖定其他寫入，逾時或部分清理不代表成功。

Availability Gate 以 `deletion.phase` 顯示後端已確認的階段，不顯示百分比。只有 Workspace 已不存在並由 API 回傳 `404` 時才算完成；前端此時才清理 query、導向 fallback 並顯示成功。失敗會保留 Workspace 與持久化資料，提供 Owner 重試。Knowledge Base 本體永遠保留，只在最終刪除提交時移除 Workspace 掛載關聯。

## 畫面狀態與唯讀行為

畫面以 `pending`、`active`、`complete`、`action_required`、`uncertain` 與 `failed` 投影 loading、empty、error、denied 與生命週期狀態。可執行動作只取自當次 API 回傳的 `allowedActions`；`stopped` 不會自動啟動，一般可恢復錯誤的 `rebuild` 需要明確確認，執行平面漂移則不提供 rebuild。只有讀取操作時保留可讀內容與一般變更控制項，但停用變更並顯示 i18n 原因；缺少讀取操作時不啟動受保護 query、Provider 或即時連線。

控制平面或身份服務的錯誤只顯示穩定 `reasonCode`，不把 provider、例外或內部回應原文送到使用者介面。背景重新整理不會重新顯示入口 Gate；切換工作區則會先清除舊內容，再以新工作區 identity 重新投影。

## 限制、失敗與安全

逾時、舊 generation 或 provider 暫時不可觀測時保留不確定或可重試狀態，不能直接顯示成功，也不能直接判定為執行平面漂移。只有確認目前 generation 的 workload 不存在、部分缺失或 identity 不符，且沒有進行中的 lifecycle 工作時，才進入漂移狀態。
