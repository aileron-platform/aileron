# 權限與角色

## 目的與入口

本頁是平台、Workspace 與知識庫授權行為的 canonical 功能說明。

## 角色與允許操作

平台角色只有 `admin/member`；資源角色只有 `owner/manager/reader`。Platform scope 依平台角色，resource scope 依有效資源角色與 Operation Requirement。

## 核心概念

`allowedOperations` 是前端共同依據；`accessSource(s)` 說明角色來自 owned、direct_share、group_share、public 或 platform_admin。

## 主要流程

Manager 驗證本地使用者快照，再檢查 operation。資源 admin override 只能提升至 manager、記錄稽核，且不能執行 owner-only 刪除。

## 畫面狀態與唯讀行為

畫面分別處理 loading、empty、error 與 denied。只有讀取操作時保留可讀內容與一般變更控制項，但停用變更並顯示 i18n 原因；缺少讀取操作時不啟動受保護 query、Provider 或即時連線。

## 限制、失敗與安全

授權欄位缺失、未知角色或來源矛盾一律 fail closed；無存取與角色不足分別維持 404／403 語意。

Manager Session 缺少、過期、撤銷或 principal binding 不一致時回傳
`401 MANAGER_SESSION_REQUIRED`，Frontend 才進入一次 OIDC 重新登入。Session 證據有效但
本機使用者政策或平台 operation 不允許時回傳 `403 PLATFORM_AUTHORIZATION_DENIED`，保留
Session 且不重新登入。
