# Permissions and Roles

## Purpose and Entry Point

This is the canonical feature description for platform, Workspace, and knowledge-base authorization behavior.

## Roles and Allowed Operations

Platform roles are `admin/member`; resource roles are `owner/manager/reader`. Platform scope uses the platform role, while resource scope uses the effective resource role and Operation Requirement.

## Core Concepts

`allowedOperations` is the frontend contract. `accessSource(s)` identifies owned, direct_share, group_share, public, or platform_admin origins.

## Primary Workflow

Manager validates the local user snapshot, then checks the operation. Resource admin override only elevates to manager, is audited, and cannot perform owner-only deletion.

## View States and Read-only Behavior

The view handles loading, empty, error, and denied states separately. With read-only operations, readable content and normal mutation controls remain visible while mutations are disabled with an i18n reason. Without read access, protected queries, providers, and realtime connections do not start.

## Constraints, Failures, and Safety

Missing authorization fields, unknown roles, or contradictory sources fail closed. Missing access and insufficient role retain 404 and 403 semantics.

A missing, expired, revoked, or principal-mismatched Manager Session returns
`401 MANAGER_SESSION_REQUIRED`, and Frontend enters OIDC reauthentication once. Valid Session
evidence with a denied local user policy or platform operation returns
`403 PLATFORM_AUTHORIZATION_DENIED`, preserves the Session, and does not reauthenticate.
