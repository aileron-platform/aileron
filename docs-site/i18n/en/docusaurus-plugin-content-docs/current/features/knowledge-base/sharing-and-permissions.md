# Sharing and Permissions

## Purpose and Entry Point

Enter Sharing and Settings from knowledge-base detail to manage direct sharing, group sharing, and public visibility.

## Roles and Allowed Operations

Detail requires reader; sharing and visibility changes require manager; permanent deletion requires owner.

## Core Concepts

Multiple access sources produce the highest effective role while retaining all sources. Public provides reader only.

## Primary Workflow

Add or remove user/group shares, change visibility, and reload the resource authorization response.

## View States and Read-only Behavior

The view handles loading, empty, error, and denied states separately. With read-only operations, readable content and normal mutation controls remain visible while mutations are disabled with an i18n reason. Without read access, protected queries, providers, and realtime connections do not start.

## Constraints, Failures, and Safety

After revocation, Frontend stops mutations according to new allowedOperations and never retains a stale role.
